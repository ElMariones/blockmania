# Localization

BLOCKMANIA's interface ships in eleven languages: English (source), Spanish, French, Italian, German, Dutch, Polish, Brazilian Portuguese, Japanese, Simplified Chinese and Traditional Chinese. The player chooses one in **Settings > Game > Language**. **SYSTEM**, the default, follows the language chosen for the game in Steam (`BMSteam.game_language()`), else the OS locale, else English (`BMLoc.resolve_with`). The Steamworks side (store languages, base languages, localized store text and achievements) is in [store/steam/LANGUAGES.md](../store/steam/LANGUAGES.md). Changing the language rebuilds the screens in place. A run, the shop or an Endless game in progress stays untouched.

## How text flows

| Kind of text | Written as | Shown with |
|---|---|---|
| UI labels, buttons, tooltips | `BMLoc.t("TEXT")`, `BMLoc.tn("1 thing", "%d things", n)` | the translation, right away |
| Catalog data (Joker names and texts, bosses, Kits, hands, tips, tutorial…) | a plain `const`, with an `# i18n` marker on its first line naming the translatable fields, e.g. `const CATALOG := [ # i18n: name, text` | the catalog's display helper (`BMJokers.display_name/display_text`, `BMBosses.title/rule_text`, `BMPieces.piece_name`…) |
| Rules text (errors, events, credit lines, run-end reasons, achievement progress) | `BMLoc.m("...")` / `BMLoc.mn(...)`: identity markers. The text stays **English** inside `BMRun`, saves and results | `BMLoc.tf(text)` at display time, which matches the English sentence against `BMMessages.PATTERNS` and formats the translation with the same arguments (translating `%s` arguments too) |

Rules and saves never contain translated text, so a save made in one language loads in any other.

Rules for code:
- Never compare against display text. Compare ids, node names or flags.
- GDScript's `%` cannot reorder arguments, so a translation keeps the source's placeholder order. Where the order must change (`{color} {shape}`), the message uses `String.format` with named placeholders.
- Whole sentences only: never glue a translated prefix to a translated suffix. Plurals go through `tn`/`mn`; Polish has three forms.
- Numbers: `BMUI.fmt_int` groups thousands with `,` (English, Japanese, Chinese) or a narrow no-break space (U+202F, the other languages). Decimals keep `.` everywhere. Lists join with `BMLoc.list_sep()` (`、` in CJK).
- Text drawn in `_draw()` wraps with `BMUI.wrap_lines`, which breaks CJK between characters. A single line drawn into a fixed width goes through `BMUI.draw_fit` (or picks its size with `BMUI.fit_size`): a longer translation steps down the grid sizes (80, 60, 40, 30, 20), and text that does not fit even at 20 is logged in `BMUI.overflows`, which the languages scenario fails on.
- A button whose text changes at runtime (counts, prices) goes through `BMUI.fit_button(button, width, size)` after the text is set.
- Buttons and labels at fixed rects: measure the text once the control is in the tree (it has the theme's font only then) and widen the rect or step the font size down, never let the minimum size silently grow the control.

## Files and tools

| Path | What |
|---|---|
| `game/i18n/loc.gd` | `BMLoc`: language list, `apply`, `t/tn/m/mn/tf`, separators |
| `game/i18n/messages.gd` | `BMMessages.PATTERNS`, generated by the extractor: every rules message with placeholders, for `tf` |
| `locale/messages.pot`, `locale/<code>.po` | gettext template and translations, loaded at runtime (`locale/*.po` is in the export include filter) |
| `tools/i18n/extract.py` | scans `BMLoc.t/tn/m/mn` literals and `# i18n` consts, writes the template and `messages.gd` |
| `tools/i18n/update_po.py` | merges the template into every `.po` (new messages come in empty, removed ones drop out) |
| `tools/i18n/check.py` | fails on an untranslated message, different placeholders, lost edge spaces or newlines, lower-case text where English is ALL CAPS, or a character with no glyph |
| `tools/art/gen_font.py` | Blockhead with Latin accents for es/fr/it/de/nl/pl/pt (accented capitals are squeezed to 6 rows under a 2-row mark so they keep the 10 px em) |
| `tools/art/gen_cjk_fonts.py` | subsets Fusion Pixel 10 px (OFL-1.1) to the characters the ja/zh_CN/zh_TW translations use, as `assets/fonts/cjk_*.ttf` fallbacks |
| `tests/e2e/scenario_languages.gd` | walks 32 screens and overlays in every language and fails on missing glyphs, text escaping its panel or the window, controls grown past their rect, cut text without a tooltip, words split mid-line, untranslated text, and drawn text or fitted buttons that do not fit even at 20 |

After changing or adding UI text:

```bash
python tools/i18n/extract.py && python tools/i18n/update_po.py
# translate the new entries in locale/*.po, then
python tools/art/gen_cjk_fonts.py      # when ja / zh_CN / zh_TW gained new characters
python tools/i18n/check.py
"<godot>" --headless --path . --script res://tests/e2e/run_e2e.gd -- languages
```

`gen_cjk_fonts.py` needs the unpacked "fusion-pixel-font-10px-proportional-ttf" release in `build/fontsrc/`. It is not committed; see THIRD_PARTY.md.

Screenshots of one language: `BM_LANG=de python tools/shoot.py fixture.gd out.png`. The game also takes `-- --lang=<code>`, which is not saved.

## Style

- Latin languages keep the game's terms **Mult** and **Chips**-style short words where the language uses them (German, Dutch). Proper names (POPS, Buru Arcade, BLOCKMANIA) stay as they are. Japanese and Chinese translate everything, Mult included (倍率).
- ALL-CAPS English stays ALL-CAPS. CJK has no case, so it uses short, bold phrasing instead.
- French uses the formal "vous" and narrow no-break spaces before `! ? : ; »` and after `«`.
- Space is tight: buttons and plates have fixed widths on the 1920×1080 stage. Prefer the shorter synonym, and check the languages scenario. Useful budgets at size 20: Joker counters 300 px (shop rack line), offer card body 224 px × 4 lines (3 with a two-line title), boss rule in the round panel 420 px × 4 lines, Bag tile label 124 px.
